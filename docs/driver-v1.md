# Simulation driver contract v1

A SimulationConfig v1 owns exact model id/modelVersion/stateVersion, dimension (0 abstract, 2 or 3), declared unit identifiers and passive JSON model.data. Scalar number/integer/boolean/enum descriptors define parameters, inputs and projected state fields. Numeric descriptors have explicit finite min/max and a valid default; enum defaults belong to unique enumerations. Unit identifiers must be declared by the model; boolean/enums have no unit. Parameter values may omit declared fields (defaults fill them) but cannot invent fields or exceed bounds. Field IDs are unique within each role; parameter/input/state names may overlap because their namespaces differ. 64 parameters/inputs,128 state fields; JSON2 MiB/depth32/1000 collection/100000 strings/50000 nodes.

The optional runtime entry initializes a trusted driver only after schema/semantic validation, exact model+state version matching, dimensions and unit inclusion, required capabilities/operations and default-deny host permissions. No same-major inference, coordinate/unit conversion, module import or generated executable code is performed. DriverManifest includes the seven standard capability declarations, domain operations step/input/reset, versioned model slots and explicit execution/network/media requirements. Driver capabilities are claims by the trusted host plugin, not a proof of determinism; Registry/Core catalog integration is a subsequent host binding. A network-required driver cannot claim offline.

Async initialize receives frozen config plus cooperative cancellation signal and returns a live handle with initialState, step, optional reset (mandatory if declared) and dispose. State projection must exactly cover descriptors with JSON scalar values; native objects, extra fields and invalid values reject. Physics bodies, WASM objects, renderer camera/colors/vendor objects stay in the trusted driver and never enter public state. Model.data may contain passive domain data, not renderer state or live handles; domain-specific schema/semantic gates remain model-owner responsibility.

Session input synchronously replaces the complete declared input map atomically; drivers read it at the next step. Parameters remain immutable for the session. step accepts seconds in (0,60], passes frozen old state/parameters/inputs to the captured driver port and atomically commits one validated projection, incrementing integer tick once. The additive fixed-step clock, seeded random source, pause/resume behavior and catch-up policy are specified in [time-stepping-v1.md](time-stepping-v1.md). Drivers must compute from supplied state and stage vendor mutations so a rejected/failed step cannot corrupt later simulation. Framework hosts use Core effects for asynchronous simulation service results, validating correlation before applying actions; this session is a domain driver facade, not a Protocol EngineSession.

Reset invokes the driver with original parameters and default inputs, validates returned projected state, sets tick0 and rotates private operation generation. Overlapping operations/input while busy reject. Initialization and asynchronous operations have 30s default deadlines (1..60000ms configurable). Caller abort, dispose or timed-out operation prevents late state application. A cancelled/timed-out step/reset disposes the session, requiring fresh initialization; a trusted synchronous domain failure leaves the prior projected state intact. Safe SimulationError code+stage distinguish validation/negotiation/initialize/input/step/reset rejections without raw host messages.

Dispose is idempotent and returns the same cleanup promise, forwarding abort to an active operation and attempting to release a handle once. Late initialized handles are released once even if the caller has already timed out. Signals and promise races do not forcibly interrupt CPU loops or vendor processes: drivers must cooperate, and hard resource/worker/process controls are host-owned. Cleanup completion relies on driver dispose; automatic release is best effort, cleanup exceptions are isolated and arbitrary noncooperative cleanup can remain pending. Hosts monitor their own driver teardown. No worker/network/physics authority is granted implicitly.

Counter fixture is a deterministic custom rate model; physics fixture uses an analytic constant-acceleration projection. CI runs real trusted fixture drivers, not Matter/Rapier, whose adapters remain later issues. Identical ordered inputs/dt produce identical states within the tested JS engine; trigonometry/vendor/platform determinism is not implied. No renderer, native snapshot format, state migration, evaluation score, events or npm publication is added. Optional owned schemas and facade preserve shared wire contracts; decisions: improvement-proposals/decisions/simulation-drivers-v1.md and improvement-proposals/decisions/simulation-clock-v1.md.
